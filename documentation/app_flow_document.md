# App Flow Document

## Onboarding and Sign-In/Sign-Up
A new visitor arrives at the public landing page served from the root URL. This page is built in `app/page.tsx` and is ready to host the Hero, Features, Testimonials, Pricing, or any custom sections you add for CodeGuide. At the top of this page, users see "Sign In" and "Sign Up" buttons provided by the `components/auth-buttons.tsx` component. Tapping "Sign Up" navigates the user to `/sign-up`, where they fill out an email and password form. This form submits to the Better Auth API endpoint under `app/api/auth/[...all]/route.ts`. On successful account creation, Better Auth issues a session cookie and automatically redirects the user to `/dashboard`. If a returning user clicks "Sign In," they are taken to `/sign-in`, complete the form, and upon valid credentials, land on the same dashboard. Signing out is available from the dashboard header, where clicking the "Sign Out" button calls the sign-out endpoint, clears the session, and returns the user to the landing page.

## Main Dashboard or Home Page
After authentication, users enter the dashboard at `/dashboard`. This page has a left-hand navigation sidebar created by `components/app-sidebar.tsx` and a top header containing the `components/theme-toggle.tsx` button and a sign-out link. The main content area currently displays sample charts and tables which act as placeholders for CodeGuide’s real features. Each link in the sidebar triggers a client-side transition to the corresponding section of the app without a full page reload. The header’s theme toggle switches between light and dark mode instantly using Tailwind CSS classes and local component state.

## Detailed Feature Flows and Page Transitions
Users begin on the marketing landing page and scroll through sections built in the root `app/page.tsx`. When they decide to register, the "Sign Up" button transitions them to `app/(auth)/sign-up/page.tsx`. That page’s form sends a POST request to the Better Auth route, which handles validation and account creation. Once the session cookie is set, Next.js automatically redirects the user to `/dashboard`. Inside the dashboard, selecting any sidebar link swaps the main content area by loading the matching component via the App Router. Clicking "Sign Out" in the header posts to `/api/auth/sign-out`, removes the cookie, and sends the user back to the landing page. If users navigate directly to `/dashboard` without an active session, the `middleware.ts` file intercepts the request and redirects them to `/sign-in`. This ensures only authenticated users see private content.

## Settings and Account Management
Currently, the only personalization control is the theme toggle in the header, which allows switching between light and dark modes. There is no dedicated settings or profile page in this starter template. However, the existing layout and sidebar make it straightforward to add a new section under `/dashboard/settings` or similar. After changing any setting, users remain within the authenticated area and can move freely between sections using the sidebar or logo link in the header.

## Error States and Alternate Paths
If a user enters invalid credentials on the sign-in page, the form displays an inline error message explaining the problem, and the user remains on `/sign-in`. Network failures during the API call trigger a generic error banner, prompting users to retry. When an unauthenticated user attempts to access a dashboard route directly, the middleware redirects them to `/sign-in`. If a session expires while browsing the dashboard, any subsequent action or page reload will route them to the sign-in page. All errors are shown in context, ensuring users know exactly how to correct their input or retry their action.

## Conclusion and Overall App Journey
A visitor begins on the public CodeGuide landing page, explores the marketing content, and chooses to register or log in. Upon authentication, they arrive in a protected dashboard featuring a sidebar, header with controls, and a main area for application features. They can toggle themes, navigate between sections instantly, and sign out at will. Throughout the experience, middleware and inline feedback maintain security and clarity, forming a complete flow from discovery to daily use in the CodeGuide application.
